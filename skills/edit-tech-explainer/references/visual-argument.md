# 从口播观点到视觉论证

## 先理解，后排版

读取完整脚本或原声及其上下文。为每段填写：目标观众、要回答的问题、作者判断、支撑依据、对象之间的关系、希望观众记住的结论。区分事实、作者分析和待核对项；没有依据时不要替作者补出因果或性能结论。

未参与写稿时，先从当前脚本还原逻辑。若两种解释会产生明显不同的画面，拿具体判断与用户对齐；不要让用户重新解释已明确的信息。不要擅改已录口播。可以另列建议，获准后再改稿。

## 按关系选择表达

| 口播要表达什么 | 合适的画面 | 判断是否有效 |
| --- | --- | --- |
| 某赛道有哪些竞品 | 主题＋品牌 Logo 同屏 | 对象身份清楚，品牌不用逐个切镜 |
| 两条策略有什么区别 | 两条并行路径，呈现各自的动作与目标 | 看得出策略如何产生结果，而非只有 ToC / ToB 标签 |
| 产品如何构成生态 | 产品与工作环节的关系图，按语义逐步强调 | 便捷、安全、省钱与具体产品有可验证的对应 |
| 为什么这样决策 | 约束／动作／结果的因果关系 | 每条连线有脚本或来源支持，推断明确为作者解读 |
| 怎样完成一个任务 | 输入／关键操作／结果，结合真实界面 | 看得出用户做什么以及得到什么 |
| 产品有什么差异 | 对齐比较维度的对照页 | 比较对象和层级一致，不捏造参数或优劣 |

一页一个观点不等于一页几个词。删去装饰和重复文字，保留使判断成立的关系。不要用统一圆角卡片代替所有图形；构图、空间层级、连线、模块与高亮应各有解释作用。

## 静态确认交付

每张独立图附：编号、完整口播语义、唯一观点、画面类型、来源、预计停留、后续变化和审核状态。策略页面同时提供一句说明：这个布局让观众理解了什么。备注放在确认稿外侧，不叠进正式画面。

新风格先提交实际内容的代表页。复杂关系图需展示完整终态及关键变化状态，让用户知道动画后会多出哪些信息。用户明确要求纯 Logo 页时按该要求执行，不能强加关系图。

## 语义与组件

为重要事件记录触发短语、实际语音区间、作用对象和动作，如“提到产品后揭示对应模块”。记录最低阅读时间与完整句子边界；原语速太快时减少信息或延续同页，不任意挪动语音。

以实际反复出现的关系建立组件：赛道 Logo 页、双路径策略页、生态关系图、发布会 Keynote 页、真实操作页。组件接受内容、来源与语义事件；配色和版式可复用，已确认项目判断不随素材替换而重写。更换口播后重新测量语义切点，不复用旧秒数。
